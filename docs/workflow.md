# 制作と校閲の手順

1. `STATUS.md` で進捗を確認し、対象話の設定・プロット・直前の状態を読む。
2. 設定と文体はbible、構成と小場面はplot、本文はwrite、検証・推敲はreviseを使う。
3. 一度に一つの小場面を書く。小場面が揃ったら結合し、場面間のつながりや重複を話全体で直す。
4. 字数と表記を確認して `main/` へ採用。本文の出典を付けて `wiki/canon/` と進捗を更新する。
5. GitHubへコミット。採用版がCloudflareへ配信される。
6. 作者が校閲画面で本文を選択し、指示を `feedback/` へ保存する。
7. エージェントが指示の引用と対象版を確認し、該当箇所を直す。数字・持ち物・日時が変わったら前後の話への影響も記録する。
8. 小場面、結合稿、採用稿を同期し、必要な検査を通す。指示へ反映結果を追記し、すべて処理したものを `feedback/done/` へ移す。
9. 変更をPRにまとめ、作者の確認を経てマージする。

依頼例:

> darask-novel-workflow と ja-novel-revise を使って、feedback/ にある第1〜4話の指示を反映して。引用を優先して位置を特定し、mainと小場面を揃えて、字数と数字を確認して。変更をPRにまとめて。

## 指示の4種類

| 種別 | 扱い |
|---|---|
| 修正 | 指定された範囲を直す |
| 増やす | 出来事・会話・反応を展開する |
| 減らす | 指定範囲を削り、必要な情報と伏線を残す |
| メモ | 気づきとして残す。本文の変更指示とは区別する |

本文は校閲中にも更新されます。段落番号がずれたら、指示の引用・コミット・本文ハッシュを使います。一致しない指示を機械置換で流し込まず、該当範囲を探してから反映します。新しい版へ持ち越された下書きは、保存した旧版の情報を保持します。

未反映の指示が残るファイルは `done/` へ移さず、理由を明記します。波及する変更が依頼範囲外なら、その話番号と食い違う内容を `STATUS.md` に残します。
