# 原稿と校閲指示の受け渡し

作品の `AGENTS.md` と `STATUS.md` を読み、今回の話数・作業範囲を確認する。ユーザーの明示指示と、作品固有の保存先・字数・確定設定を優先する。

## 正本

- `main/NNN.txt`: 採用本文。題名・作業記録を混ぜない。
- `plot/episodes.json`: 話番号、題名、本文パス。`plot/episodes/` は詳細設計、`plot/beats/` は小場面の順序。
- `wiki/`: 未出を含む設定・文体。`wiki/canon/` は採用本文に出た事実と出典。
- `work/scenes/`: 組み立て用の小場面。`work/drafts/` は結合稿。
- `feedback/`: 作者の指示。`feedback/done/`: 処理済み指示と反映記録。

設定は `ja-novel-bible`、構成は `ja-novel-plot`、執筆は `ja-novel-write`、推敲は `ja-novel-revise` を、必要な工程だけ使う。未導入ならその事実を示し、利用できる作品資料から進める。別工程への切替だけのために同じ許可を取り直さない。

## 校閲指示を反映する

1. 対象のfeedback、対象版の本文、関連する設定を読む。段落番号より引用を優先し、コミットや本文ハッシュで版を区別する。引用が見つからなければ類似箇所を自動置換せず、未特定として残す。
2. `修正`は指定範囲、`増やす`は出来事と応答の展開、`減らす`は必要情報を残す削減。`メモ`は本文への変更指示と区別する。明示された新しい指示が古い設定と違う場合は、変更の適用範囲を記録する。結果を左右する曖昧さだけ確認する。
3. 必要な区間を直し、対応する小場面へ差分を戻してから結合する。章を丸ごと生成し直して指定外の差分を広げない。複数話に波及する金額・日時・持ち物・人物の知識を照合する。
4. 作品のコマンドで字数、必要な表記、結合と採用稿の同期を確認する。汎用版は `python scripts/novel.py check`。実行していない検査を確認済みとしない。警報は文脈で採否を決める。
5. `wiki/canon/` の該当事実に採用本文の引用と位置を付け直し、必要なプロット・索引・STATUSを更新する。新設定を作者の確定事項へ自動昇格させない。
6. 指示ごとの反映結果と例外を元feedbackへ追記する。全件処理したファイルを `done/` へ移す。未処理が残る場合は元の場所で理由を示す。
7. Git差分を確認し、依頼された範囲でコミット・PRを作る。PRに指示ファイルと反映結果、検証結果、残る影響を記載する。送信・公開・マージはユーザーの依頼や既存の許可の範囲で行う。

## 配信する

`scripts/build_site.py` は索引に登録された採用本文とリーダーを `_site/` へ集める。設定・未来のプロット・認証情報を配信物へ混ぜない。作品のGitHub送信先とCloudflareの配信先を確認し、既存の認証・Access設定を維持する。設定が足りない場合も、先にローカルのビルドと確認を終える。

作品内の公開操作と、投稿先への小説投稿は別々の操作として扱う。校閲リーダーから届いた指示があるだけで、未依頼の全作品改稿や公開設定変更を始めない。
