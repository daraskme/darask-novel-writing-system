# 設定・文体管理

次の書き手が人物の行動と声を判断できる基準を作る。設定の作成・更新を担当し、本文への適用は `ja-novel-write`、原稿との照合・修正は `ja-novel-revise` の担当とする。基準を確かめる短い見本台詞や文体試作はここで作ってよい。

`SKILL_DIR` はこのファイルのディレクトリ。`RESOURCE_DIR` は、`SKILL_DIR` に `references/` があれば `SKILL_DIR`、それ以外は 2 階層上のリポジトリルート。参照資料中の `SKILL_DIR` は共通資源のルート `RESOURCE_DIR` と読み替える。

## 依頼の範囲と資料

- 依頼された設定だけを作る。口調だけの相談に世界年表やプロジェクト一式を追加しない。短い作品は会話や `notes.md` の必要な欄で完了できる。
- 既存作品では、`STATUS.md` があれば作業位置を確認し、対象人物・場所・時点に関係する設定と本文だけを読む。新規作品ではユーザーの条件を使い、未指定の細部は案として具体化する。
- 明示された設定・変更指示を優先する。結果を左右する矛盾や不足だけを確認し、名前・語尾・試作ごとの一律の承認待ちは設けない。
- 他工程との連携や既存作品の台帳更新を行うときは [共通の引継ぎと記録](references/workflow.md) を読む。
- 長編プロジェクトを作る・既存原稿を取り込む場合は [長編運用](references/longform.md) の「再開と初期化」、章の事実・状態・伏線実績を記録する場合は同資料の「bible：台帳更新」を読む。`facts.jsonl` など機械が読む形式はそこで確認する。

## 作る基準

| 依頼 | 残すもの | 必要な参照 |
|---|---|---|
| 世界観・舞台 | 今回効く世界の規則、場所、組織、能力や技術の限界 | [世界設定の雛形](assets/templates/world.md)。ジャンル固有の約束が要る場合だけ [ジャンル](references/genres.md) の該当節 |
| 人物・関係・口調 | 欲求と行動の根拠、相手別呼称、語彙・語尾・応じ方、状況による変化 | [人物設計](references/character.md)、[人物シート](assets/templates/character.md) |
| 地の文の文体 | 人称・視点、時制、語りの距離、文末、文と段落の方針、基準見本 | [文体シート](references/style-sheet.md)、[雛形](assets/templates/style-sheet.md) |
| 用語・表記・既出事実 | 正式表記、呼称の適用時点、出典のある出来事・状態、未確定の候補 | [用語と呼称の形式](assets/templates/glossary.toml)、[共通の引継ぎと記録](references/workflow.md) |

全員を語尾だけで区別しない。一人称の表記、相手への呼び方、敬語、語彙、発話の長さ、言い淀み方を必要に応じて組み合わせる。「普段は敬語、弟と二人きりでは常体」のように、変化の条件も基準に含める。

地の文の文体と人物の台詞は別に定義する。一人称の語りなど両者が重なる場合は、語っている時点と相手の違いを記す。見本がある場合は実際の特徴を抽出し、一般的な読みやすさに合わせて整えない。試作は文体確認の成果物で、原稿や作中の既出事実にはしない。

## 正本と更新

プロジェクト形式があるときは既存の保存先と形式を維持する。

| 情報 | 正本 |
|---|---|
| 世界の基準・場所 | `bible/world.md` |
| 人物の基準・声・関係 | `bible/characters/` の人物シート |
| 地の文の文体 | `style/style-sheet.md`。共有する値は `novel.toml` と揃える |
| 用語・相手別呼称・世界制約 | `style/glossary.toml` |
| 本文で起きた事実と章末の状態 | `canon/`。出典と確定状態を付ける |
| 今後起こす変化 | `plan/` と `plot/`。計画の管理は `ja-novel-plot` |

- 世界設定にある事実、人物が知っている事実、読者へ既に提示した事実を分ける。設定資料が渡されたことだけで、人物や読者の既知にはしない。
- 本文で追加された設定は `proposed` とし、モデルの判断だけで `confirmed` へ昇格させない。ユーザーの明示的な採用・改定指示や既存の許可があるものは、改めて確認を求めず根拠を記録して反映する。
- 意図された人物の変化には開始章と原因を記録する。将来の変化を現在の口調へ先取りせず、過去章の作業ではその時点の状態を使う。
- 確定した文体基準を、新しい生成原稿に合わせて自動で更新しない。基準の変更と、原稿の逸脱は分けて扱う。

台帳を変更したときは、変更した ID・時点・呼称・事実の整合を確認する。プロジェクト全体の参照を更新した場合は必要に応じて `python "RESOURCE_DIR/scripts/ledger_lint.py" --project DIR` を使う。警報は確認候補で、本文や設定を機械的に書き換える命令ではない。実測が必要な文体分析には `novel_lint.py --stats` を使える。詳しい引数は各スクリプトの `--help`。

## 完了と引継ぎ

設定資料または設定案、今回の変更点、未決のうち後工程に影響するものを示して完了する。相談だけならファイル保存を必須にしない。複合依頼では、使う基準・適用時点・確定状態・保存先を次工程へ渡し、依頼された工程だけ続ける。担当の分離は別エージェントの起動を意味しない。他のスキルが利用できなくても、必要な後処理は同梱の参照を使って完了し、機械的な引継ぎのための再依頼を求めない。
