# 日本語小説の検証・推敲

原稿を作品の設定・文体・プロットと照合し、根拠のある問題を依頼範囲で直す。既存の声を保ち、警報数や自己採点を良くするために文章を均さない。

`SKILL_DIR` はこのファイルのディレクトリ。`RESOURCE_DIR` は、`SKILL_DIR` に `references/` があれば `SKILL_DIR`、なければ 2 階層上のリポジトリルート。参照資料内の `SKILL_DIR` は `RESOURCE_DIR` に読み替える。

## 範囲を決める

依頼から、対象の章・箇所と、検証だけか修正までか、どの層を扱うかを決める。既に指定・許可された作業を再確認しない。「講評して」は診断、「誤字だけ直して」は表記の訂正、「口調だけ合わせて」は口調の修正まで行う。単に「推敲して」なら既存の筋・人物・結末を維持した文章の修正を進める。

| 層 | 照合するもの | 修正の境界 |
|---|---|---|
| 表記・数値 | 原稿、媒体の指定、表記方針、計算結果 | 誤字や一意に決まる誤り。人物の意図的な言い間違いは別扱い |
| 設定・口調 | 人物シート、相手別呼称、状況別の口調、既出事実と状態 | 原稿の逸脱を直す。例外のある口調を一律の語尾へ変えない |
| 展開・伝達 | プロットの意図と固定条件、本文の因果、読者の既知 | 欠落や動機不足を示す。大きな筋・人物・結末の変更は依頼が含む範囲だけ |
| 全体調整 | 結合した章・複数章・作品全体、区間の入口と出口、字数配分 | 接続、重複、時系列、山場の厚みを整える。必要な再配置や局所の書き直しを含む |
| 文章 | 原稿の声、文体シート、語りの距離、文の働き | 反復、主述、説明、リズムを直す。好みだけの変更を増やさない |

資料がなければ本文内の整合と依頼の基準で確認し、外部設定まで検証したと言わない。全体調整を頼まれた場合は、必要な区間の再配置や局所の書き直しまで進め、実施内容をプロット担当へ戻す。確定世界設定や結末を勝手に変えない。設定そのものや大きな筋の変更が必要なら、`ja-novel-bible` / `ja-novel-plot` へ渡す変更案として整理する。連携時だけ [共通運用](references/workflow.md) と [longform.md](references/longform.md) の該当工程を読む。

## 診断して直す

1. **原稿と根拠を読む。** 保存された対象版を読み、残す声や表現を把握する。詳細な直し方は [revision.md](references/revision.md)。症状で頼まれたら同資料の「症状から引く」から必要な節を選ぶ。
2. **問題を位置と根拠で示す。** 「引用・何が起きているか・根拠・直す方向」を短く記す。設定矛盾は本文と設定／既出本文の対、口調の逸脱は相手と状況、数値の誤りは検算を添える。作者が AI かどうかを判定しない。
3. **必要な検査だけを使う。** `python "RESOURCE_DIR/scripts/novel_lint.py" <原稿> --project <作品ルート>`。プロジェクトがなければ `--length` と `--profile` を指定し、表記だけなら `--only NCM` に絞る。字数条件には `count_chars.py`。警報は疑う箇所であり誤りの確定ではない。[ai-tells.md](references/ai-tells.md) は問題のカテゴリだけ読む。
4. **依頼範囲の差分を作る。** 診断だけの依頼では原稿を変更しない。修正依頼なら旧版を残し、該当箇所へ反映する。書き直しは一度に 1 区間、800〜2,000 字程度を見当とし、局所修正をその量へ引き延ばさない。章全体の再生成で差分を消さず、新設定で都合よく矛盾を埋めない。
5. **影響を確認する。** 差分、前後のつながり、守る表現、関連設定と知識状態、字数条件を見る。変更の影響がある検査だけを再実行する。改善したら終了し、好みの往復や警報ゼロを目指す周回をしない。

## 結合後の全体調整

小場面を結合した後は、章・複数章・全体のうち依頼された範囲を通して読む。重点は、区間をまたぐ行動と知識・持ち物・時間のつながり、繰り返された導入・前提説明・結び、口調と文体のずれ、山場と通過部分の分量である。短い区間の生成を一つずつ整えただけで、全体が整ったと判断しない。

直す区間の ID と短い指示（何を保ち、何を移す・削る・展開するか）を作り、区間単位で反映して再結合する。分割草稿があればそこへ差分を入れて章本文と揃える。章本文へ直接直した箇所は、再結合前に対応する区間へ戻す。ID のない旧ビートは、並べ替え・挿入・削除の前に現在の代替 ID（`s01` 等）を明記し、保存済み区間との対応を固定する。区間を再配置した場合は、プロット担当とビートの配列順を揃えてから再結合する。プロジェクトの再結合は `python "RESOURCE_DIR/scripts/assemble_scenes.py" --project PROJECT --chapter N --overwrite`。古い草稿で章本文を上書きしない。変更した入口・出口・順序はプロットへ、本文の事実と状態は設定管理へ根拠つきで戻す。

全体調整は結合後のまとまりに対して行い、800 字ごとの生成や短い一場面の依頼に毎回義務化しない。詳しい観点は [revision.md](references/revision.md) の「結合した本文の全体調整」。

## 独立レビューが必要なとき

読後の反応、構成の伝わり方、大きな改稿の比較には [review-protocol.md](references/review-protocol.md) を使う。別コンテキストへ原稿と必要最小限の資料を渡す。スキル分割や役名変更だけでは独立レビューにならず、同一コンテキストの再読を盲検と呼ばない。

校正や局所修正に複数のレビュー役を必須にしない。レビューの指摘も原稿・作品方針と照合して採否を決める。点数は依頼された場合だけ返し、点数を修正の目標にしない。外部サービスへの原稿送信は明示された許可の範囲で行い、既存の許可を再確認しない。

## 提出と任意の書き出し

- 依頼に合わせ、根拠つき指摘、修正原稿、変更点または差分を返す。未確認事項や範囲外の重要な問題だけを添え、作業記録で本文を埋めない。
- 設定・既出事実・伏線に波及する変更は、対応する管理担当へ本文の根拠とともに戻す。検証側で確定設定や未来の計画を上書きしない。
- 投稿用ファイルが必要なら [notation.md](references/notation.md) と `python "RESOURCE_DIR/scripts/export.py" --help` を確認し、指定形式へ書き出して `--verify` で内容の保持を確かめる。応募規定は対象の最新要項で確認する。ファイルの作成と外部への投稿は別の操作として扱う。
