# 人物設計

人物・関係・声の基準を作るとき、または基準自体の不足を直すときに読む。執筆中は作品の人物シートと呼称表を使い、原稿の照合・修正は検証・推敲の工程で行う。

雛形は [人物シート](../assets/templates/character.md)。長編の人物 ID、呼称の適用章、変化の記録の形式はそのまま使う。掌編は「欲しいもの・相手との関係・声の特徴」が数行あればよく、全項目を作らない。

## 1. 行動を導く人物の核

属性の一覧より、場面で選択を分ける情報を残す。「几帳面」なら「釣り銭を硬貨の大きい順に渡す」のように行動へ落とす。行動の理由には、信念・仕事・利害・過去の経験のどれが効いているかを添える。

| 項目 | 判断に使える形 | 例: 運行管理者の茂木律子 |
|---|---|---|
| 欲しいもの | 今、何を得ようとしているか | 自分の担当中に無事故日数を途切れさせない |
| 信念と行動 | 何を信じ、だから何をするか | 確認すれば防げる → 他人の確認を信用せずやり直す |
| 欠点 | その選択が何を損なうか | 若手の報告書を書き直し、若手が報告を控えるようになる |
| 妥協できない点 | しないことと、それが試される条件 | 記録を後から直さない。直せば若手の免職を防げる場合は揺れる |
| 能力 | 出所・範囲・上限・効かない条件 | 配車は頭に入っているが、欠勤が重なると抱え込んで崩れる |
| 自己像とのずれ | 本人の説明と、実際の行動の違い | 自分は慎重だと思うが、人を待てずに手を出す |

欠落、誤った信念、成長は全人物の必須条件ではない。本人が変わらず周囲を変える主人公、完成した専門家、日常の端役も成立する。雛形の欄は必要に応じて短くし、使わない項目を埋めるための傷や奇癖を足さない。

身体・社会・心理を分けて見ると、設定のつながりを点検しやすい。律子の「腕時計を手首の内側に着ける」は、元運転士としてハンドルを握りながら読んだ習慣で、身体と経歴がつながっている。外見や生い立ちを増やすより、現在の行動へ効く事実を残す。年齢・生年・勤続年数を固定するときは日付との関係を計算する。

## 2. 声シート

声は語尾だけで作らない。話す相手、何をさせたいか、どう見られたいかが、敬語・語彙・文の長さに現れる。すべての軸を人物間で変える必要はなく、その人物を識別できる差を選ぶ。

| 軸 | 記録するもの | 注意点 |
|---|---|---|
| 一人称 | 語と表記、相手や状況で切り替わる条件 | 「私／わたし」も区別。主語を毎回言わせる必要はない |
| 二人称・呼称 | 名前、役職、親族呼称、呼ばない相手 | 日本語の台詞へ「あなた／君」を機械的に補わない |
| 敬語 | 基本段階、相手別の差、感情や同席者による変化 | 怒ると丁寧になる人、焦ると常体になる人もいる |
| 語彙 | 和語・漢語・業界語などの層と、その出所 | 時代や本人の知識範囲を越えない。世代を流行語だけで示さない |
| 文の長さ・止め方 | 用件と理由の順、言い切り、言いさし、沈黙 | 三点リーダー以外にも接続助詞や省略で間を作れる |
| 応じ方 | 復唱、即答、聞き返し、冗談、別件へ逃げる等 | 全員をはぐらかす人にせず、問いの重要度でも変える |
| 語尾・口癖 | 常用する形と、出る条件 | 毎発話に付けず、場面の用件を優先する |

敬語は上下関係だけでなく内と外で変わる。「所長がおっしゃるには」と「所長の塚越が申しておりました」は、同じ相手について話していても聞き手が違う。接客で覚えた不慣れな敬語など、意図した特徴は明記して校正による消失を防ぐ。

語尾の例も働きで決める。「〜けど」で判断を預ける、「〜から」で結論を省く、「〜というか」で言い直す、相槌を復唱で返す。語尾が同じでも、用件を短く切る人と、前置きの長い人は違って聞こえる。

役割語、女性語、方言、音の引き伸ばしは作品の様式で選ぶ。属性から自動で割り当てたり、ジャンル名だけで禁止したりしない。実在の方言の地域差・世代差に確信が無い場合は、その不確かさを残し、必要な語を資料で確かめる。未確認の造語を土地の正しい言葉と断定しない。

### 条件つきの声の例

```text
茂木律子
- 根拠: 元運転士。無線と点呼の言葉が身についている。
- 一人称: 職場は「私」、弟と実家では「あたし」。
- 呼称: 職場は名字＋さん／役職。弟だけ「あんた」。
- 敬語: 普段はです・ます。腹を立てると尊敬語・謙譲語が増え、文は短くなる。
- 語彙: 業務の略語を使い、時刻は分まで言う。抽象的な説明は少ない。
- 応じ方: 指示を問いの形で出す。相槌は復唱。
- 見本台詞（基準用。作中の出来事や定型台詞にはしない）
  平常: 「七時十二分の桐生駅行き、六号でお願いします。六号です」
  苛立ち: 「所長。点呼は、私がいたします」
  外の人へ: 「所長の塚越は車庫におります」
  弟へ: 「あんたさ、チャイルドシート、いつ取りに来んの」
```

平常の一文だけでなく、実際の出番に関係する状況の見本を置く。見本は調子を合わせるためのものなので、その文を全場面へ繰り返さない。試作で偶然生まれた経歴や出来事を設定として確定しない。

### 同じ用件、違う声

六号車に擦り傷があり、事故報告はない。

- ベテラン運転士: 「六号、左のうしろ。見といて。朝の洗車んときにはもうあった。言っとくけど俺じゃない」
- 本社から来た所長: 「六号車の件なんですけど。接触痕があるみたいで、報告、上がってきてないですよね。いや、責めてるわけじゃなくて」
- 律子から所長へ: 「事故報告は上がっていません。きのうの出庫分から点呼簿をさかのぼります。十時までにまとめます」

違いは語尾のほか、情報の順番、弁明の先取り、用語、時刻を区切る態度にある。既存の複数人物の声が近い場合は、こうした差から見直す。

## 3. 呼称・敬語段階表

相手別の呼称の正本は `style/glossary.toml` の `[[address]]`。人物シートは要約、文体シートは方針を持つ。短い作品では `notes.md` の表でもよい。

```toml
[[address]]
from = "C01"
to = "C03"
call = "所長"
from_ch = 0
note = "職場はです・ます。腹を立てると敬語が増える。外の人には『所長の塚越』"
```

- `from / to / call / note / from_ch` の形式を維持する。地の文は `from = "地の文"`。開始章を省略するか `0` にすると初期の呼称になる。
- `build_context.py` は対象章より前に開始した、同じ組の最新の呼称を使う。その章の途中で起きる変更は、章ビートにも明記する。
- 呼称が変わったら旧項目を消さず、`from_ch` を付けて追加する。人前と二人きりの違いなど、同時に存在する条件差は `note` に書く。
- 変化を予定しただけなら章ビートに置く。本文でまだ和解していない二人の呼称を先に変えない。
- 原稿の呼称が表と違うだけで表を追認更新しない。条件つきの正当な使用、設定変更の候補、原稿の誤りを見分ける。用語 lint は、この意味判断の代わりにはならない。

## 4. 関係と敵役

「姉」「上司」など世界の関係と、対照・障害・証人など作劇上の役割を分ける。脇役にもその人自身の用事を持たせると、必要なときだけ現れる助け手になるのを避けられる。

対立が必要な作品では、双方について「退けば具体的に何を失うか」を考える。和解できる第三案があるなら、交渉で解く展開も使える。対立を維持するためだけに人物を不合理にしない。

敵役の設計には次の観点が使える。

| 型 | 残す根拠 | 避ける都合 |
|---|---|---|
| 計画で動く相手 | 目的、使える情報、見落とす範囲 | 終盤だけ知能を下げる |
| 理想で動く相手 | 守る価値と、他者へ負担を強いる理由 | 論破されるためだけの信念 |
| 味方の顔をした相手 | 親切ごとの本当の目的 | 伏線のない豹変、露見だけで別人になる口調 |

全作品に強敵や二者択一を設ける必要はない。協働、親密さ、役割の違いも関係を動かす。

## 5. 名前の付け方と出番の深さ

名前は作品の時代・文化・家庭の命名の癖に合うものを選ぶ。実在の姓名分布や歴史上の流行を根拠にする場合は資料で確認する。異世界なら言語圏ごとの音や名前の順の方針を揃える。

作品内で字面や音が近い名前は識別しづらくなるので一覧で確認する。似ていることを狙う場合は残してよい。候補選び自体が依頼でなければ、一律に複数案を出して選択待ちにしない。仮名を使うなら未確定と分かるようにし、既出の名前は依頼のない推敲で替えない。

- 主役: 主要な選択と、重要な相手に対する声が導ける深さ。
- 脇役: 自分の目的、主役との関係、識別できる声。
- 端役: その場での役割と用件。不要な来歴は足さない。

## 6. 動かして確かめる・名前隠しテスト

設計が曖昧なときは、境界が試される短い状況へ人物を置き、選択・行動・台詞・理由を試す。たとえば律子なら、検知器は正常だが目の赤い運転士しか始発を運転できない状況。声だけが問題なら、同席者が変わる会話だけで足りる。

試作は確認したい不確かさに合わせる。固定本数の試作やユーザーへの評定を毎回必須にしない。違和感が出たら語尾を増やす前に、信念、相手との関係、敬語の条件を見直す。

話者の識別が問題になった場合は、台詞から名前・発話タグを外して読む方法が使える。さらに語尾や一人称を均した版を比べると、語尾だけに依存しているかが分かる。ただし、全員の口調を極端に離すことを目標にしない。似た声に意味がある作品や二人きりの会話もある。独立した読者で試すときは [レビュー手順](review-protocol.md) の声の識別テストを使う。設計者自身の判定を独立した読者の反応として扱わない。

## 7. 章またぎの変化と未決項目

人物シートの本体は開始時点の基準を持ち、その後の変化を適用時点の分かる履歴へ記録する。`## 変化の記録` の `- ch005〜: 内容` という形式を維持し、表にはしない。これはコンテキスト生成が対象章より前の記録だけを使うためにも必要になる。

起きた変化には出典章と原因を付ける。今後起こす予定は `plan/structure.md` と章ビートへ置く。過去の章を扱うときは、その時点の呼称・知識・関係を使う。作者が知る秘密と、本人の認識は別に記録する。

新しい生成原稿だけを理由に確定基準を更新しない。設定候補・本文から確認できる事実・ユーザーが採用した変更を区別する。`proposed / confirmed` と記録の更新順は [共通の引継ぎと記録](workflow.md) に従う。
